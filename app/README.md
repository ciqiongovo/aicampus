# InfoAgent

以邮件为入口的个人信息整理与行动辅助系统（桌面软件）。

技术栈：Electron（>=34） + React 18 + TypeScript + Vite（electron-vite）+ Ant Design 5。
界面由模块注册表驱动：JARVIS（Agent 工作台：多轮对话、工具调用与审批、记忆与规则）、面板（AI 推荐与反馈）、日报、邮件、待办（清单与任务）、日程（周/日时间轴）、资料（文件夹与独立标签）、聊天记录（微信/QQ 导入）、设置。

## 启动方式

日常使用：双击本目录的 **`InfoAgent.exe`**（约 116 KB 的启动器）。它立刻启动同目录的 **`app\InfoAgent.exe`**（解包运行集，约 510 MB），无需安装、无需解包，双击即开。数据保存在系统 userData 目录，替换程序目录不会丢数据。

启动器会在启动前清掉 `ELECTRON_RUN_AS_NODE`、`NODE_OPTIONS`（被开发工具注入时 Electron 会以 Node 模式静默退出，表现为“双击没反应”）；`app\` 缺失或启动失败时弹框说明具体原因，不再一声不响。

需先从系统托盘**完全退出**正在运行的 InfoAgent 再双击：程序只允许单实例，否则只会唤醒旧窗口。

改完源码后重新打包：`pnpm run publish:exe` 会把单文件便携版写到 `release\`，并**覆盖**根目录的 `InfoAgent.exe`（启动器）。要保持秒开，需把 `release\win-unpacked\` 的内容同步到 `app\`，再用 `DSHprogramfiles\聊天记录\2026-10-18-双击启动\launcher.cs` 重新编译启动器（`csc /target:winexe /optimize+ /win32icon:resources\icon.ico`）。

### 开发 / 重新构建入口

双击根目录 `启动InfoAgent.bat`，按提示选择：

- 1 = 开发模式（热更新，改代码即时生效）
- 2 = 直接启动构建版（默认，5 秒后自动执行）
- 3 = 重新构建并启动（代码有改动后选这个）

脚本会自动挑选本机 Electron 运行时（优先 `D:\Projects\InfoAgent\electron-dist`，退回 `node_modules\electron`），并清除开发工具注入的环境变量。关闭窗口会进入托盘；托盘图标可恢复或退出。

## 开发命令

    pnpm install --registry=https://registry.npmmirror.com   # 安装依赖（Electron 走 npmmirror 镜像）
    pnpm dev        # 开发模式（热更新）
    pnpm typecheck  # 类型检查
    pnpm test       # 单元测试（db/mail/ai/items/panel/workspace/daily/counterRec/im 等）
    pnpm test:panel # 只跑面板推荐与反馈闭环测试
    pnpm build      # 构建到 out/
    pnpm dist       # 打包 NSIS 安装程序 + portable 单文件版

## 信息面板（推荐与反馈闭环）

- 来源不写死：`inbox_source` 表登记来源（当前内置邮件、手动摘录、日报），邮件同步与分析继续由原链路写入 `info`；新增来源只需登记 `source_key` 并提供适配器。
- 首批只读近期一小批：首次打开最多 20 条、近 14 天；读完由用户点“继续阅读下一批”，避免启动时把全部历史交给模型。
- 推荐：本地规则先粗排（时效、截止、事件、主题、历史偏好），配置并授权 AI 后一次性批量判断并给出推荐动作与理由；未配置时自动退回本地规则，页面可用。
- 动作目录在 `src/shared/panel.ts` 一处维护：忽略、存为资料、设为日程、放入待办；采纳即执行，改选会作为纠正信号。
- 学习只记“主题”和“来源”：`feedback_event` 记录每次采纳/改选，`preference_signal` 按八类主题与来源累积权重，21 天半衰期衰减；不再记录动作和发件人。主题词表与“资料”共用 `src/shared/topics.ts`，不再使用旧的分析分类。
- “存为资料”由用户选择文件夹或新建文件夹，默认未分组；资料栏有独立搜索、文件夹与 AI 标签筛选，文件夹可自由新建、重命名、删除，支持批量移动、删除与手动新建资料；标签存于 `material_tags`，和邮件的 `mail-tags.json` 是两套库。

## 目录结构

    src/main/        主进程：窗口、托盘、IPC、设置存储、业务服务
    src/preload/     contextBridge 白名单 API
    src/renderer/    React 界面（模块注册表驱动导航）
    src/shared/      前后端共享类型与 IPC 通道常量
    tests/           单元测试
    resources/       图标与托盘资源（electron-builder buildResources）

数据与设置存放于系统 userData 目录（与安装目录分离）。

## 2026-10-18 更新

- JARVIS 会话列表支持删除，确认后清理该会话的消息、附件和执行记录。有正在运行或等待确认的任务时，须先停止任务。
- 面板邮件日期筛选默认 7 天内，可选 1、3、7、14、30 天内及 30 天前，重点邮件与其他邮件共用筛选；数量及分页同步更新。
- 日期按邮件发送时间和本地自然日计算，近 N 天包含今天，30 天前指距今天至少 30 天；非邮件来源不受影响。

- 修复日期参数在 IPC 接口被丢弃的问题，日期选项现已实际作用于查询。
- 待办支持批量管理：全选当前视图、批量完成、移动清单、删除（含提醒）。
- 资料文件夹改为用户自建，保存可选择目录或新建目录；默认未分组。旧资料目录保留，支持批量移动、移出资料库，以及手动新建资料。
- 数据库升级至 v23；首次启动升级前自动保存一致性备份，位于原数据库目录下的 `infoagent.db.pre-v23-*.bak`。

## 面板邮件 / QQ 更新（2026-10-18）

- 面板左上角的「信息来源」可切换邮件与 QQ 群聊；邮件保持重点/其他分组和发送日期筛选，QQ 单独显示消息切片。
- QQ 默认展示近 3 天消息，可选 1、7、30 天内和 30 天前，日期按消息所在的本地自然日筛选。
- QQ 视图增加与邮件栏一致的筛选：按结论类型（决定/待办/事实/链接/待确认/主题）切换标签，并可筛选待处理、已采纳、已忽略。
- 近 3 天收到、尚未读且分析出截止时间的邮件会优先进入推荐批次，并在重点邮件中显示醒目的「紧急」标记；点击邮件标题即可进入邮件详情，从面板进入时点「返回面板」直接回到面板。
- QQ 条目显示消息时间；点条目里的「原文」可查看支撑该结论的聊天原文。
- 关键词画像是全局画像：邮件处置和 QQ 结论的采纳/忽略都会更新同一份关键词；邮件单次反馈权重为 0.32，QQ 为 0.16，两者都受 14 天重复窗口与 ±3 上限约束。
- 首次启动含 v25 的版本会清空既有邮件推荐、反馈及据此学习的画像，让新一轮反馈从零开始；已建资料、待办和邮件原文保持原状。升级前的数据库快照位于 userData 下的 `infoagent.db.pre-v25-*.bak`。
- 数据库升级至 v26：关键词画像增加邮件/QQ 来源计数，反馈表改为按来源记录；升级前自动保存一致性备份，位于原数据库目录下的 `infoagent.db.pre-v26-*.bak`。

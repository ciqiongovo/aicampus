# 知枢 · 高校活动对标

> 想知道别的学校的学生会在办什么、怎么办的，打开它，几分钟出一份带原文链接的简报。

上海科技大学「AI 赋能行政应用大赛」参赛作品。原本是一个个人信息工作台（InfoAgent），
这一版把主线换成跨校对标——公众号采集放在第一位，邮件、日程、待办退到后面当辅助。

---

## 别人怎么拿到它

结论：现在把 GitHub 链接发给别人，他既打不开，也跑不起来。仓库 `ciqiongovo/aicampus`
是**私有**的（未登录访问直接 404），而且只放源码——`.gitignore` 排除了 `release/`、
`out-dist*/` 和体验包目录，GitHub 上没有任何可运行的 exe，Release 也一个都没有。

按省事程度，三种给法：

| 给谁 | 发什么 | 对方要做什么 |
|---|---|---|
| 只想看结果 | [`output/知枢-对标报告-示例.html`](output/知枢-对标报告-示例.html)（68 KB） | 双击打开，Ctrl+P 存 PDF。不装东西、不联网 |
| 想试软件 | `output/知枢-体验包.zip`（约 155 MB） | **整个文件夹解压** → 双击「知枢.exe」；自带 13 校 / 39 场示例库，不碰他已有数据 |
| 自己长期用 | `ZhiShu-1.0.0-portable.exe`（约 106 MB） | 双击；数据落在 `%APPDATA%\ZhiShu` |

zip 和 exe 是本机构建产物，不进仓库（几百 MB，没必要让 clone 变慢）；报告 HTML 和
干净示例库在本仓库里，clone 下来就能看效果——示例库只含对标数据（29 校 / 42 源 /
93 篇 / 39 场），没有邮件正文、账号和密钥。要拿它跑软件，把它改名成 `zhishu.db`
放到 `%APPDATA%\ZhiShu\`；或在 exe 同目录建一个 `data\` 放进去，再放一个空的
「知枢-便携数据.flag」，数据就只读写包内，不碰系统目录。

**一定要走 GitHub 的话**：先把仓库改成 Public——私有仓库的 Release 资产同样要登录才下得了；
再建一个 Release，把 zip / exe 作为资产传上去，别人从 Releases 页下载。不想公开代码
就别走这条路，把体验者加为 collaborator，或者直接用上面的文件发给他。

发出去之前核一遍校验和：

```
知枢-体验包.zip            sha256  40341ef7f44ce2e6f4a2c605ed588535cc5dea21d3f2e5f8dc44473ae0b17ffb
ZhiShu-1.0.0-portable.exe  sha256  feed463c6b6195563ec5f2863e2138c9af0052b5324b67172c7392bda779351f
知枢-对标报告-示例.html     sha256  d475b5184daa5d237f7044ab0f0424d2fad267aabfcf6b8b9c6d73aceaa9fa11
```

开发者自己从源码构建（Node 22）：

```bash
cd app
npm install
npm run dist:portable   # 产物在 app/release/
```

## 两种交付分别是什么

下面这些路径都是**本机**的构建 / 分发产物，不是仓库里的文件：

```
app/release/ZhiShu-1.0.0-portable.exe   # 单文件，双击即用，不需要装 Node，也不需要装微信
output/知枢-体验包/                      # 整个文件夹，双击里面的「知枢.exe」
```

**给别人看效果，用体验包。** 里面已经放了一份干净的示例库（13 所学校、39 场活动，
只有对标数据，没有邮件、账号和密钥）：同目录的「知枢-便携数据.flag」会让软件把数据读写
限定在包内 `data/`，不碰对方电脑上已有的库。整个文件夹拷到 U 盘或发给同事，双击就能看到
对标页、简报和「同一件事，各校怎么办」，不用联网，也不用先采一遍数据。删掉那个 flag，
软件就回到默认数据目录。包里另有「知枢-对标报告-示例.html」，不装软件也能看，Ctrl+P 可存 PDF。

**自己长期用，用单文件 exe。** 第一次启动会在 `%APPDATA%\ZhiShu\` 建库，
换电脑拷这个目录数据就跟着走；卸载或删掉 exe 不会碰它。第一次启动会自解压到临时目录，
之后每次启动大约两三秒。

安装包版（`npm run dist` 生成的 NSIS setup）会建桌面快捷方式，其余行为一致；当前只打了便携版。

## 三步

**① 选学校。** 界面上列了上海 29 所高校，本校（上科大）带紫色标。点某所学校的「一键采集」，
它按「校名＋学生会 / 团委 / 研究生会」这类常见写法去搜这个学校的公众号文章，搜到就顺手采正文、
抽字段（不想采就把「搜完顺手采正文」的开关关掉，只收链接）。
上科大用的是一批查证过的真名（上海科技大学学生会、上科大学工部团委、书院的天空……），不用猜。
每所学校几十秒——每个账号之间要停三五秒，搜太快会立刻被搜索引擎要求验证码。

懒得一所一所点，就用「补齐最缺的 5 所」：它自动挑出文章最少的那几所依次搜一遍，
中途撞上验证码会自己收工，并告诉你补到了哪几所。

**② 采内容。** 采集正文要真的把文章页渲染出来：公众号文章是 JS 外壳，直接抓源码拿不到字。
每篇间隔 2.5–5.5 秒，一次最多跑 20 篇，按钮上带括号数字告诉你还剩多少。
「跑完队列」会一直推到空为止（单次上限 60 篇），撞上验证码会自己停手。
抽字段默认走规则（不需要模型 key）；配了模型之后会多出议程、特色环节、可迁移性这类更细的字段。

**③ 看结果。** 按学校、类型、时间、关键词筛，然后生成简报或并排对比。

简报抽屉分两页：

- **横向对比**——先把「谁和谁差在哪」摆出来。本校作为基准排第一行，
  规模、提前多久发预告、办在第几周、合办比例各占一列，下面配类型与宣传手段的分布。
  结论一律带数字，比如「本校中位提前 11 天发预告，外校 3 天——我们早了 8 天」。
  某一项只有不到两所学校有数据时，那一列干脆不出现：校园活动报道普遍不写人数，
  摆一列「—」只会让人以为抽取坏了，所以改在结论里直说「这项原文普遍没写」。
- **同类活动**（在「横向对比」页签的下半部分）——换一个切法：按活动类型横着看。
  选「迎新与毕业」，下面是各校同一类活动的卡片，一场一张：哪天、第几周、提前几天预告、
  在哪办、面向谁、要不要抢票、谁协办、有什么特色。上面还有一句小结
  「5 所学校共 20 场，多在第 4 周，中位提前 4 天发预告，8 场在礼堂与剧场」。
  各校一览回答「谁办得多」，这一节回答「我要办这一场，别人怎么办的」。
  只有一所学校的类型不列——一所学校的两场是它自己的重复，不是对照。
- **简报原文**——纯文本，能直接粘进 Word、群聊，也能「存成 Markdown」。

右上角「导出报告」出一份 HTML：样式全写在文件里，不引任何外部资源，
双击就能看，Ctrl+P 直接印成 A4 交上去。别人电脑上能不能打开，不取决于他有没有网。

**两件数据清理的活。** 「公众号源」抽屉里有体检：默认列出不属于上海任何一所高校的号
（早期搜索没加引号时被拆词匹配带进来的别校稿子、营销号），勾选后一起删，删之前能逐个取消勾选。
每个号的学校也能改——「青春SUES」这种名字里没有校名的，认出来就归位，别当成垃圾删。
另外单篇详情里有一个「不是活动」按钮：规则抽取偶尔会把「院长一行访问某校」当成沙龙分享，
点一下就把这条剔除，原文仍留在库里。

## 数据从哪儿来，边界在哪

全部来自公开的公众号推文。没有接微信的任何私有接口，也没有做批量爬取。

- **搜索入口**：移动版百度（`m.baidu.com`）。公众号正文不被必应、360 收录，搜狗微信已改成验证码拦截。
- **账号名必须加引号**：`site:mp.weixin.qq.com "上海科技大学学生会"`。不加引号会被拆成三个词去配，
  返回的全是别校的「学生会」稿子——实测 25 篇里只有 4 篇属于目标学校。
- **配额是硬的**：一个出口 IP 大约连查 4–5 次就要凉一会儿。所以一次只查五六个账号，
  被拦就停手，界面直接说「过 20–30 分钟再试」，而不是让人对着一串失败反复点。
- **搜到的是被收录的那部分**，不是这个号的全部历史。要看全，只能手工粘链接导入。
- **本校条件**在设置里可改，可迁移性判断（「这事我们能不能照做」）就按那段描述给。

做不到的也不藏：原文删了标「原文已删」，正文全是图标「纯图」，时间没写写「原文未写」，
周次是按日期推的就标「约」。

## 每场活动抽这些

| 字段 | 说明 |
|---|---|
| 活动类型 | 迎新晚会、毕业季活动、竞赛、讲座…… |
| 举办周次（约） | 按学期开学日推算，各校校历不同，只作参考 |
| 时间 / 时长 / 地点 / 规模 | 原文写了才填，不补 |
| 组织方式 / 协办 | 线下独办、与学院合办、需报名筛选…… |
| 面向 / 参与方式 / 宣传形式 | |
| 议程 / 特色环节 | 议程是流程，特色是别人没有的那几处，两者刻意分开 |
| 可迁移性 / 依据 | 现成条件可办 / 协调后可行 / 门槛较高 / 不适合搬，附一句话理由 |

## 目录

```
app/                    桌面应用（Electron + React + TypeScript）
  src/main/services/benchmark/   采集、判定、抽取、横向对比、简报与报告
  src/renderer/src/modules/      界面
tools/bench/            命令行工具（与界面共用同一套 DAO 和判定）
docs/                   设计与口径文档
```

命令行能做同样的事，批量补数据时更省事：

```bash
node tools/bench/dist/cli.mjs stats
node tools/bench/dist/cli.mjs discover 复旦大学 --limit 5
node tools/bench/dist/cli.mjs fetch --limit 20
node tools/bench/dist/cli.mjs extract
node tools/bench/dist/cli.mjs brief --out brief.md
```

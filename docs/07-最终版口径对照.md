# 最终版报名表口径 → 开发对应

2026-11-12 晚收到「最终版」（`上海科技大学AI赋能行政应用大赛报名表-知枢-v3(1).docx`，案例报告 631 字）。
以它为准，此前我写的 974 字版本作废。下面只记「口径变了什么、代码怎么跟」。

## 一、四处实质变化

| | 旧（我写的 v3） | 最终版 | 开发影响 |
|---|---|---|---|
| 定位 | 对标库 + 校内收件台，两条腿 | **一套自动筛选系统**：接口输入 → 按标准采集过滤 → 精炼输出 | 收件台降为「理论也可接入邮箱等其他输入端」，不再是卖点；主线是对标库 |
| 范围 | 首批二十所兄弟高校 | **上海其他高校**学生会、团委 | 数据以在沪高校为主；不设 region 字段，用学校名筛（扩到全国时再加） |
| 字段 | 活动类型、主办方、时间、地点、对象、参与方式、宣传形式 | 活动类型、**举办周次**、**组织方式**、宣传形式 | 加 `week_no`、`org_form`；日期仍留作原始依据 |
| 用法 | 筛选对比、二次通知提醒 | ①**借鉴**：一年内全部活动 + **自动判断能否迁移到本校** ②**查细节**：某类活动的**议程与特色环节**一次看全 | 加 `migration_fit`/`migration_note`、`agenda`；前端加「近一年」与类型筛选 |

参赛方向也改了：原「面向师生服务」→ **「面向决策支持」**。

## 二、已经落到代码里的

- `week_no`：提示词要求原文写了「第 X 周」才填，**不许拿日期反推**（各校校历不同，反推必错）
- `org_form`：线下独办 / 线上线下结合 / 与学院合办 / 需报名筛选等
- `agenda`：只抽原文真正写出来的环节，不许按「晚会一般都有开场致辞」补
- `migration_fit`：easy / possible / hard / unsuitable 四档，提示词里内置本校条件（本科生规模、可借场地、单场预算上限），并要求理由指向原文具体做法
- 前端：「近一年 / 近半年 / 全部」+ 学校 + 类型 + 关键词 + 只看二次通知

## 三、还没做

- **简报导出**（最终版承诺「几分钟出一份带原文链接的简报」）：M3 第一项，未开始
- 本校条件目前是写死的常量（`services/benchmark/extractor.ts` 的 `OUR_CONTEXT`）。真正上线要挪到设置页，否则可迁移性判断按「一般大学」的想象给，对本校没用
- 地域限定没有字段，只靠学校名。要在界面明确写「上海高校」，别让人以为全国都有了

## 四、一句话原则

最终版把产品讲成「筛子」，那就让每一条能力都能落到一个可以点出来的操作为止：
筛选条件能调、字段能看、原文能跳、不能办的能说清为什么。凡是做不到这一点的表述，都不要写进表里。

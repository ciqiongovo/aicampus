## 三、一个待解决的依赖

`tools/im-connector/src/main/services/im/chatlog.ts` 依赖 **chatlog** 这个 Go 写的本地 HTTP 侧车（127.0.0.1:5030）。chatlog 已于 2025-10 被微信官方函件下架，现在是拿不到的。

好消息是这个文件本身写得克制——注释原话：「这里只依赖 HTTP，不关心它内部怎么解密；接其它实现（PyWxDump、自研 sidecar）时换掉本类即可。」

本地已有自研解密能力（`repos/b/wechat-decrypt-main`，frida 抓 key + 解密 20 个库，已跑通）。所以补一个 HTTP 适配层就能把 im-connector 复活。但**不建议**为了报名表去承诺群消息自动汇入：那意味着系统要读全班群聊，与「涉及师生个人信息的数据已脱敏」的承诺相冲，出问题的代价远大于收益。v3 报名表写「邮件与**转发的**消息汇入」就是这个考虑。

## 四、改造路线

**M1 跑起来（1 天）**
`app/` 内 `pnpm install` → `pnpm dev`，确认基线可启动、邮件事务可读、数据库迁移正常。不改业务。

**M2 对标库最小闭环（进行中，2026-11-12 21:2x 起）**
已落地 `app/src/` 下这批文件，改成先跑通「链接进 → 字段出」，不先接微信库：
- `shared/benchmark.ts`：类型与 IPC 通道；`articleUrlKey()` 用 `__biz+mid+idx` 做去重键（同一篇被反复转发只会入队一次）
- `main/db/benchmarkSchema.ts`：迁移 v30，三张表 `bench_source` / `bench_article` / `bench_activity`
- `main/db/dao/benchmarkDao.ts`：全部 SQL；入队靠唯一键 `ON CONFLICT DO NOTHING`，抓取失败区分 `deleted` 与 `unreachable`
- `main/services/benchmark/fetcher.ts`：隐藏 BrowserWindow 渲染 + 页内取字段（不回传 4MB DOM），UA 伪装成普通 Chrome
- `main/services/benchmark/extractor.ts`：先判是否活动，再填七个字段；原文没写的留空，不补全
- `main/services/benchmark/service.ts`：串行编排（并发会被公众号风控）
- `main/ipc/benchmark.ts` + `preload/benchmark.ts` + 页面 `modules/benchmark.tsx`

验收：三十所清单里的任意一校，能点出它最近 10 篇活动，字段可读、链接可跳。

**M2.5 接本地微信库自动发现新链接（下一步）**
现在的入口是「粘贴链接」。要变成真正的「按清单自动读新推文」，得在主进程里解微信本地库
（`biz_message_0.db` 的 `message_content` 是 zstd 压缩）。Python 侧已验证可行（见 docs/05），
Node 侧需要 zstd 解压 + AES 解密，或用 spawn 调 sidecar。

**M3 简报与排期（2–3 天）**
对标简报导出（带原文链接）；活动立项倒排 + 撞期提示。
